Architecture of the CPU

The fetch–execute cycle and Von Neumann registers

The central processing unit (CPU) processes instructions. In a stored-program computer, instructions and data are held in main memory and the CPU repeatedly fetches, decodes and executes instructions.

3 EXPLANATION PANELS

The fetch–decode–execute cycle

Fetch: the CPU obtains the next instruction from main memory. Decode: the control unit interprets what operation is required. Execute: the operation takes place: perhaps a calculation, comparison, memory access or input/output action. The cycle then repeats.

The program counter (PC) identifies the address of the next instruction to be fetched, and is updated as the program progresses. A branch may change the next instruction address.

The main CPU components

PartJob
Control unit (CU)Decodes instructions and coordinates/control signals for the CPU.
Arithmetic logic unit (ALU)Performs arithmetic and logical operations.
CacheSmall, fast memory near or inside the CPU storing frequently used instructions/data to reduce slower RAM access.
RegistersVery small, very fast storage locations used while processing instructions.

Von Neumann registers: what exactly is stored?

RegisterContains
MAR — memory address registerThe address of a memory location to be accessed.
MDR — memory data registerThe data or instruction being transferred to/from memory.
PC — program counterThe address of the next instruction.
AccumulatorIntermediate data/results of calculations made by the ALU.

An address tells the CPU where in memory; data is the value or instruction stored at that location. You need the purposes of these registers, but not a register-by-register transfer sequence for every fetch cycle.

EXAM POINTER → Address = where; data = what. Do not confuse MAR and MDR.

Indicative points to include

A developed, well-explained point may earn credit in more than one way; these are not official OCR mark schemes.

Exam technique

J277/01 · 80 MARKS · 90 MIN

  1. Read the command word: describe, explain, compare or discuss.
  2. Use precise subject vocabulary: don’t say “it is faster” without saying why.
  3. For scenarios, mention the specific device, user or organisation.
  4. For discussions, develop benefits and disadvantages and provide a justified judgement.
  5. Check calculations: units, multiplication, divide by 8, and overflow.
  6. No calculator: practise binary/hex conversions and file-size arithmetic mentally/on paper.

The suggested points are a learning checklist; actual OCR marking may credit other correct approaches.
