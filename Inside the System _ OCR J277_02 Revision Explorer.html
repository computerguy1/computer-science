2.1.1

Computational thinking

Abstraction

A school canteen app needs item names, prices and stock counts. It does not need the colour of the kitchen walls. Abstraction produces a model containing the details that matter for this purpose; a different purpose may need different details.

Decomposition

Split the app into choosing items, validating quantities, calculating a total, taking payment and updating stock. Each part can be designed and tested separately before integration.

Algorithmic thinking

Specify an unambiguous order: read an item; reject an unknown item; read and validate quantity; calculate price × quantity; accumulate the total. Decide how repetition ends and what happens for unusual inputs.

Worked example

Problem: calculate a shopping total
Inputs: item prices and quantities
Process: validate; multiply; accumulate
Output: total cost
Refinement: reject quantities below 1
Watch for this: Abstraction removes irrelevant detail; decomposition breaks the problem into parts. Neither means simply making the program shorter.

Recall without the notes

A bus-route planner is being designed. Give one use of each computational-thinking principle.

Reveal a suggested answer

Abstraction: retain stops and travel times but omit bus paint colours. Decomposition: separate route selection, fare calculation and display. Algorithmic thinking: define exact steps to compare routes and return a suitable route.

Read the current algorithm in Python

Read and recognise the operations; you do not need to memorise the full code. The stepper exposes more intermediate states than this compact implementation.

def linear_search(values, target):
    for index in range(len(values)):
        if values[index] == target:
            return index
    return -1
How to recognise the five algorithms

Linear search: inspect items in order. Binary search: compare a midpoint and halve a sorted range. Bubble sort: compare adjacent items. Insertion sort: insert the next value into a sorted prefix. Merge sort: split, then combine sorted parts. Different valid implementations can produce different intermediate steps.

2.4.1
Translate a safety rule into logic
A heater H should turn on when temperature is low (L=1) and the window is not open (W=0). Write its Boolean expression, name the gates needed, and evaluate H for L=1,W=1 and L=0,W=0. Explain the purpose of the NOT gate.
Indicative answer & self-check
H = L AND NOT W. A NOT gate inverts W; its output and L feed an AND gate. With L=1,W=1, H=0. With L=0,W=0, H=0. NOT converts the window-open signal into a window-closed condition, so heating requires both low temperature and a closed window.
